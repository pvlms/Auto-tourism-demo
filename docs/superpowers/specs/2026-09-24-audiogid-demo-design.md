# Аудиогид — демо-прототип: дизайн

Дата: 2026-09-24
Источник идеи: `Приложение Аудиогид (Портал и мобильное приложение).txt`

## 1. Цель и рамки

**Цель.** Кликабельный демо-прототип для показа инвесторам/партнёрам, который за 5–7 минут
демонстрирует УТП: «интеллектуальный помощник для автопутешествий — контекстные истории,
проактивная безопасность и интегрированные сервисы в одном приложении».

**Критерий успеха.** Ведущий открывает приложение в браузере и за несколько минут показывает:
1. рассказ сам запускается при подъезде к объекту и становится подробнее при остановке;
2. карточку сервиса (кафе/отель), появившуюся по контексту;
3. предупреждение о ДТП и перестроение маршрута с новыми объектами по пути;
4. голосовой (или текстовый) запрос «Расскажи про …», запускающий рассказ.

**Входит:**
- веб-приложение в рамке смартфона + панель режиссёра рядом;
- симулированная поездка по реальной дороге Новомосковск → Тула → Р-132 → Калуга
  (финиш — усадьба Толмачёвых, Калуга);
- 4 функции: контекстный гид, предиктивные сервисы, проактивная безопасность с
  перестроением маршрута, голосовое/текстовое управление;
- озвучка и распознавание речи средствами браузера (Web Speech API, `ru-RU`).

**Не входит (YAGNI):**
- бэкенд, учётные записи, база данных;
- реальный GPS, реальные бронирования/платежи/заказы;
- веб-портал для авторов контента;
- нативное мобильное приложение;
- реальные данные о пробках/ДТП/погоде.

**Допущения:**
- Тексты об объектах пишутся по общеизвестным фактам и помечаются в данных полем
  `needsFactCheck: true`. Текст об усадьбе Толмачёвых — явная заглушка
  (`placeholder: true`) для замены заказчиком.
- Все кафе, отели, автосервисы и аптеки вымышленные; в интерфейсе действия
  подтверждаются пометкой «(демо)».
- Целевой браузер для показа — десктопный Chrome. Остальные браузеры — с деградацией
  (см. §6).
- Для тайлов карты нужен интернет.

## 2. Стек

Vite + React 18 + TypeScript (strict), Leaflet (тайлы OpenStreetMap-совместимого
провайдера, тёмная подложка), Vitest. Без Redux/Zustand, без UI-китов.
Сборка — статика (`npm run build` → `dist/`).

## 3. Архитектура

Три слоя, зависимости строго сверху вниз:

```
UI (React) ──команды / подписка──▶ Движок поездки (чистый TS) ──▶ Данные (JSON/TS)
   │                                        │
   └── Речь (Web Speech) ◀── события ───────┘
```

Движок не импортирует React, Leaflet и браузерные API — только данные и собственные модули.
Это делает его тестируемым в Node и переносимым в будущее мобильное приложение.

### 3.2 Данные

```ts
type LatLng = [number, number];

interface Route {
  id: 'main' | 'detour';
  points: LatLng[];            // геометрия
}

interface Poi {
  id: string;
  name: string;                // «Тульский кремль»
  aliases: string[];           // для голосового поиска: ['тула', 'кремль', 'тульский кремль']
  position: LatLng;
  routes: Route['id'][];       // на каких маршрутах объект «по пути»
  short: string;               // 2–4 предложения, в движении
  detailed: string;            // 6–10 предложений, при остановке
  needsFactCheck?: boolean;
  placeholder?: boolean;
}

type ServiceKind = 'cafe' | 'hotel' | 'autoservice' | 'pharmacy';

interface Service {
  id: string;
  kind: ServiceKind;
  name: string;
  position: LatLng;
  routes: Route['id'][];
  rating: number;              // 3.5–5.0
  details: {                   // по виду
    menu?: { name: string; price: number }[];
    freeRooms?: number; pricePerNight?: number;
    hours?: string;
  };
}

interface Incident {
  id: string;
  kind: 'accident' | 'roadwork';
  title: string;               // «ДТП на Р-132, затор 4 км»
  source: string;              // «ГИБДД · данные водителей» — показывает агрегацию
  positionKm: number;          // где на main-маршруте
  delayMin: number;            // сколько потеряешь, если ехать напрямую
  detourRouteId: 'detour';
}
```

Дополнительно у `Poi`: `leadKm?: number` (свой запас для короткого рассказа, например
для Калуги 8 км) и `isDestination?: true` (финиш — по прибытии звучит его подробный рассказ).
У `Incident`: `warnAtKm` (километр основного маршрута, где появляется предупреждение) и
`detourPoiIds` (объекты, которые есть только на объезде). Тип `TripData` (всё, что нужно
движку) описан в `src/data/types.ts`, собирается в `src/data/index.ts`.

**Маршруты (проверено по OSRM 2026-09-24):**
- основной: Новомосковск → Тула (кремль) → Р-132 (Алешня, Алексинский округ, Ферзиковский и
  Перемышльский округа) → Калуга, ≈ 168 км;
- объезд «с открытиями»: ответвляется в Туле (≈ 59,7 км основного маршрута), идёт через
  Заокский район и Алексин, пересекает Оку и через Ферзиковский округ приходит в Калугу,
  ≈ 199 км (+31 км, ≈ +21 мин при 90 км/ч) против задержки +35 мин в заторе на Р-132.

**Объекты гида (8):** Новомосковск (старт, оба маршрута), Тульский кремль (оба),
«Калужская земля» у границы областей (только основной), Алексин (только объезд),
Ока у Алексина (только объезд), Калуга (оба, `leadKm` 8), усадьба Толмачёвых (оба,
`isDestination`, заглушка, координаты — центр Калуги до уточнения).

**Сервисы:** 6 кафе, 4 отеля (один без свободных номеров — для проверки фильтра),
2 автосервиса, 2 аптеки; координаты — точки самих маршрутов, чтобы «впереди» было
всегда определено.

**Инцидент:** ДТП на Р-132 у Алешни, `positionKm` 92, `warnAtKm` 45 (подъезд к Туле),
`delayMin` 35, `detourPoiIds` = Алексин, Ока.

Геометрия маршрутов получается скриптом `scripts/fetch-routes.mjs` через публичный OSRM
(`router.project-osrm.org`) один раз и коммитится в `src/data/routes.json`
(`{ main, detour, branchKm }`); в рантайме OSRM не вызывается. `branchKm` — километр,
где объезд расходится с основным маршрутом; объезд — полный маршрут от старта до финиша,
совпадающий с основным до `branchKm`.

## 4. Движок поездки

### 4.1 Состояние

```ts
interface TripState {
  status: 'idle' | 'driving' | 'stopped' | 'paused' | 'arrived';
  routeId: 'main' | 'detour';
  distanceKm: number;          // пройдено по текущему маршруту
  totalKm: number;             // длина текущего маршрута
  position: LatLng;
  speedKmh: number;            // константа 90 при driving, 0 иначе
  timeScale: number;           // 1…20, множитель симуляции
  simClockMin: number;         // симулированное время суток, старт 11:30 (к обеду 12:30 машина уже за Тулой)
  drivingSinceStopMin: number; // для усталости
  sinceMealMin: number;        // для голода
  guide: { current: GuideItem | null; queue: GuideItem[]; seen: string[] }; // ключи уже поставленных в очередь
  incident: { status: 'none' | 'warning' | 'straight' | 'detour' | 'cleared'; canDetour: boolean; /* + тексты и цена объезда */ };
  offer: { reason: 'hunger' | 'fatigue' | 'query'; kind: ServiceKind; message: string; items: { service: Service; aheadKm: number }[] } | null;
  stats: { stories: number; services: number; detours: number };
}
type GuideItem = { key: string; poiId: string | null; title: string;
                   mode: 'greeting' | 'short' | 'detailed' | 'answer' | 'notice'; text: string };
```

Скорость фиксирована (90 км/ч) — YAGNI; ускорение показа задаёт `timeScale`.
Поездка ~150–200 км при 90 км/ч — это ~2 ч симуляции; при `timeScale` 20 (по умолчанию)
чистая езда занимает ~6 мин. Ведущий меняет `timeScale` в диапазоне 1…30.

### 4.2 `tick(dtMs)` — единственный способ продвинуть время

1. Если `status !== 'driving'` — только время стоянки (`stopped` сбрасывает `drivingSinceStopMin`
   и накапливает время стоянки для подробного рассказа); `paused` — ничего.
2. `distanceKm += speedKmh * dtHours * timeScale`; `position = pointAt(route, distanceKm)`.
3. Часы: `simClockMin`, `drivingSinceStopMin`, `sinceMealMin` растут на симулированное время.
4. Правила гида, потребностей и инцидентов → массив `TripEvent`.
5. На конце маршрута → `status = 'arrived'`, событие `arrived`.

`tick` чистый относительно внешнего мира: только меняет состояние, не вызывает озвучку.
Источник правды — состояние: стор замечает смену `guide.current` и озвучивает её,
отдельный поток событий не нужен. Предупреждения и ответы сервисов тоже идут через очередь
гида (режим `notice`). `dt` ограничивается 1000 мс, чтобы после фоновой вкладки машина
не «перепрыгнула» объекты.

### 4.3 Правила гида (`guide.ts`)

- **Короткий рассказ заранее:** когда расстояние по маршруту до проекции объекта ≤
  `max(1 км, скорость × 60 с)` и объект ещё впереди → в очередь `short`.
- **Подробный при остановке:** если машина в статусе `stopped` ≥ 3 с реального времени
  (по часам показа, не симуляции) и в пределах 3 км от объекта → `detailed`
  (если ещё не звучал). Порог в реальных секундах, чтобы не зависеть от `timeScale`.
- **Без повторов:** каждая пара (объект, режим) звучит максимум один раз.
- **Без наложений:** один `current`; остальные ждут в очереди. `detailed` вытесняет `short`
  того же объекта (прерывает его).
- **Ответ на запрос:** `tellAbout(poiId)` ставит `answer` в начало очереди, прерывая текущий
  `short`; повторный запрос о том же объекте разрешён.
- Окончание рассказа сообщает UI/речь: `guideFinished()` → следующий из очереди.
- Приветствие при старте: `greeting` с общим текстом о маршруте.

### 4.4 Предиктивные сервисы (`needs.ts`)

- **Голод:** автоматически, если `sinceMealMin ≥ 150` или часы 12:30–14:00 и
  `sinceMealMin ≥ 90`; вручную — кнопкой «Голод». Предлагает до 3 кафе впереди
  по маршруту в пределах 30 км, по возрастанию расстояния.
- **Усталость:** автоматически, если `drivingSinceStopMin ≥ 120`; вручную — «Усталость».
  Предлагает до 3 отелей впереди (или в конечном городе), с `freeRooms > 0`.
- **Запрос:** «найди кафе/отель/сервис/аптеку» — до 3 ближайших впереди выбранного вида.
- Каждая автоматическая потребность срабатывает не чаще раза в 60 мин симуляции.
- Действия в карточке: «Предзаказ» (кафе), «Забронировать» (отель), «Маршрут» (любой) —
  результат только визуальный «Готово (демо)», `sinceMealMin = 0` после предзаказа,
  `stats.services++`.

### 4.5 Инциденты и перестроение (`incidents.ts`)

- Инцидент активируется кнопкой «ДТП впереди» (если он ещё впереди на основном маршруте)
  или автоматически, когда машина на основном маршруте проходит `warnAtKm`
  (один раз за поездку).
- Пока предупреждение ждёт решения, симуляция не продвигает машину (демо-условность,
  чтобы ведущий успел выбрать; время на часах тоже стоит).
- Событие `incident` → баннер с источниками («ГИБДД · метеослужба · данные водителей —
  отфильтровано ИИ») и выбором:
  - **«Прямо»**: +`delayMin` к ETA, маршрут не меняется;
  - **«Объезд с открытиями»**: время и км объезда + список объектов, есть только на `detour`.
- `chooseDetour()`: переключает `routeId` на `detour`, пересчитывает `distanceKm` проекцией
  текущей позиции на новую ломаную, `stats.detours++`.
- Если машина уже проехала точку начала объезда — предлагается только «Прямо».

### 4.6 Намерения (`intents.ts`)

`parseIntent(text): Intent`, регистронезависимо, `ё`=`е`:
- `tell` — «расскажи/что это/что за» + совпадение по `name`/`aliases` (подстрока, затем
  расстояние Левенштейна ≤ 2 по словам); без объекта → ближайший впереди;
- `find` — «найди/где/хочу» + кафе|поесть|еда / отель|ночлег|переночевать / сервис|шиномонтаж|
  ремонт / аптека;
- `ahead` — «что впереди/что дальше»;
- `pause` / `resume` — «пауза/стоп» / «продолжай/поехали»;
- `unknown` → ответ-подсказка.

## 5. UI

### 5.1 Компоновка

Широкий экран: слева по центру рамка смартфона (≈390×844, масштабируется по высоте
окна), справа панель режиссёра. Узкий экран (< 900 px): панель режиссёра — раскрывающаяся
шторка снизу.

Внутри телефона (тёмная тема, акцент тёплый янтарный):
- `TopBar` — «До {город} {км} · {ч мин}», скорость, часы симуляции;
- `MapView` — Leaflet, тёмные тайлы; линия маршрута (пройденная часть приглушена),
  маркер машины, значки объектов (гид) и сервисов; карта следует за машиной;
  при объезде — старый участок пунктиром, новый ярко;
- `GuideCard` — внизу: название, режим («в пути» / «подробно» / «ответ»), субтитры,
  кнопка «пропустить»;
- `ServiceSheet` — выезжающая шторка с карточками сервисов и причиной
  («Вы в пути 1 ч 40 мин — время перекусить»);
- `AlertBanner` + `RouteChoice` — поверх карты сверху;
- `VoiceBar` — кнопка микрофона + поле ввода + последний ответ;
- `TripSummary` — по прибытии: км, число историй, сервисов, объездов.

### 5.2 Панель режиссёра

«Старт» (также разблокирует звук), «Пауза/Продолжить», ползунок скорости, «Остановиться /
Поехать», «Голод», «Усталость», «ДТП впереди», «Сброс», переключатель «Озвучка вкл/выкл»,
подсказка со сценарием показа (шаги 1–8).

### 5.3 Сценарий показа

1. Старт в Новомосковске — приветствие + короткий рассказ о городе.
2. «Голод» — карточка кафе впереди (Тула), «Предзаказ» → «Готово (демо)».
3. Подъезд к Туле (45 км) — само появляется предупреждение о ДТП на Р-132, выбор
   «Объезд с открытиями» (через Алексин).
4. Тула — короткий рассказ запускается сам; «Остановиться» → подробный рассказ.
5. «Поехать» — рассказы об Алексине и Оке (есть только на объезде).
6. Голос: «Расскажи про усадьбу Толмачёвых» — краткий рассказ до подъезда.
7. «Усталость» — отели Калуги со свободными номерами.
8. Прибытие к усадьбе — подробный рассказ + итоговый экран.

Шаги 3, 4 (короткий рассказ), 5 и 8 работают и без кнопок; кнопки ускоряют показ.

### 5.4 Связь с движком

`tripStore` владеет `TripEngine`, крутит `requestAnimationFrame`, вызывает `tick(dt)`,
передаёт события в `tts` и уведомляет подписчиков. Компоненты читают состояние через
`useSyncExternalStore` и шлют команды (`start`, `pause`, `setTimeScale`, `stop`, `drive`,
`triggerHunger`, `triggerFatigue`, `triggerIncident`, `chooseDetour`, `chooseStraight`,
`tellAbout`, `handleText`, `bookService`, `reset`).

## 6. Речь и деградация

- **TTS:** голос `ru-RU` из `speechSynthesis.getVoices()` (с ожиданием `voiceschanged`);
  окончание фразы → `guideFinished()`. Если голоса нет или озвучка выключена — субтитры
  показываются, окончание рассказа эмулируется таймером по длине текста
  (~14 символов/с), пометка «озвучка недоступна».
- **STT:** `SpeechRecognition || webkitSpeechRecognition`, `lang = 'ru-RU'`,
  одиночная фраза. Нет API → кнопка микрофона скрыта; отказ в доступе → подсказка
  «Разрешите микрофон или введите текст». Текстовый ввод работает всегда.
- **Автовоспроизведение:** первая озвучка только после нажатия «Старт».
- **Тайлы:** при ошибке загрузки маршрут, машина и объекты рисуются поверх пустого
  тёмного фона; сообщение не требуется.
- **Непонятная команда:** «Не понял. Попробуйте: „Расскажи про Тулу“, „Найди кафе“».

## 7. Тестирование

- **Движок — TDD на Vitest:**
  - `geo`: длина ломаной, `pointAt` на краях и в середине, проекция точки;
  - `trip`: движение с `timeScale`, пауза, остановка, прибытие;
  - `guide`: `short` запускается заранее на расстоянии, зависящем от скорости; `detailed`
    при остановке; отсутствие повторов; очередь без наложений; `answer` прерывает `short`;
  - `needs`: пороги голода/усталости, выбор только сервисов «впереди» и нужного маршрута,
    ограничение частоты;
  - `incidents`: автоактивация по дистанции, переключение на объезд с корректным
    `distanceKm`, запрет объезда после точки ответвления;
  - `intents`: все виды намерений, алиасы, `ё`, опечатки.
- **Данные:** тест, что каждый объект/сервис лежит ≤ 3 км от своих маршрутов, а объезд
  начинается и заканчивается на основном маршруте.
- **UI:** ручная проверка во встроенном браузере — полный проход сценария §5.3;
  `tsc --noEmit` и `npm run build` без ошибок.
